# Integration

This document lists the actual exported API and shows who calls it. It
covers both binding layers: the `#[wasm_bindgen]` functions
(`src/wasm.rs`, consumed by JS/TS) and the C ABI `wc_*` functions
(`src/ffi.rs`, consumed by Dart via `dart:ffi`) — the two are the same
underlying logic (`src/core.rs`) exposed two different ways for two
different platforms.

## Exported API — WASM / JavaScript-TypeScript (`src/wasm.rs`)

This is what `pkg-web/wallet_core.d.ts` (generated by `wasm-bindgen`,
see DEPLOYMENT.md) actually declares, cross-checked against `src/wasm.rs`'s
own doc comments:

### `class WcKeypair`

```ts
export class WcKeypair {
    address: string;
    privateKeyHex: string;
}
```

A generated/imported keypair, returned to JS as a plain object with two
string fields. Returned by `generateKeypair`, `keypairFromPrivateKey`,
and `keypairFromMnemonic` below.

### Functions

| Function | Signature (from `wallet_core.d.ts`) | What it does |
|---|---|---|
| `generateKeypair` | `(): WcKeypair` | Generates a fresh keypair from CSPRNG entropy. |
| `keypairFromPrivateKey` | `(private_key_hex: string): WcKeypair` | Parses a hex private key (0x-prefixed or not, case-insensitive) and returns its `{privateKeyHex, address}` pair. Throws on malformed input. |
| `addressFromPrivateKey` | `(private_key_hex: string): string` | Same as above but returns only the address. |
| `signPersonal` | `(private_key_hex: string, message: string): string` | Signs a UTF-8 string with EIP-191 `personal_sign`, returns a base64-encoded 65-byte (r,s,v) signature. |
| `signPersonalBytes` | `(private_key_hex: string, message: Uint8Array): string` | Same as `signPersonal` but for raw bytes (e.g. a pre-computed transaction digest that isn't valid UTF-8). |
| `verifyPersonal` | `(address: string, message: string, signature_b64: string): boolean` | Verifies a base64 EIP-191 signature against a claimed address. |
| `recoverPersonalSigner` | `(message: string, signature_b64: string): string` | Recovers the signer's address from a signature, without needing a claimed address to check against. |
| `generateMnemonic` | `(): string` | Generates a fresh 12-word BIP39 mnemonic. |
| `keypairFromMnemonic` | `(mnemonic: string, index: number): WcKeypair` | Derives a keypair from a BIP39 mnemonic at BIP44 path `m/44'/60'/0'/0/{index}`. |

Fallible functions throw a JS exception (a `JsValue` wrapping the Rust
error's `Display` string, e.g. `"invalid private key"`) rather than
returning a Rust-style `Result` — this is `wasm-bindgen`'s standard
`Result<T, JsValue>` → "throws on Err" convention.

### Minimal TypeScript usage example

Based on the actual exported API above and how `app-web`'s
`trovoSDK.ts` uses it today:

```ts
// walletDemo.ts
import init, {
  generateKeypair,
  keypairFromMnemonic,
  signPersonal,
  verifyPersonal,
} from './walletCore/wallet_core.js'; // path relative to this file's own location

// wasm-bindgen's `--target web` output is an ES module that must be
// initialized once (it loads and instantiates the .wasm binary) before
// any of its exports can be called.
await init();

// Generate a brand-new keypair.
const keypair = generateKeypair();
console.log(keypair.address);        // e.g. "0xfB69...5d359"
console.log(keypair.privateKeyHex);  // "0x...", keep this secret

// Derive a keypair deterministically from a mnemonic instead.
const mnemonicKeypair = keypairFromMnemonic(
  'abandon abandon abandon abandon abandon abandon abandon abandon abandon abandon abandon about',
  0, // account index
);

// Sign a message and verify it.
const signature = signPersonal(keypair.privateKeyHex, 'hello base');
const isValid = verifyPersonal(keypair.address, 'hello base', signature);
console.log(isValid); // true
```

## Exported API — native / Dart FFI (`src/ffi.rs`)

The C ABI surface consumed by `app-mobile`'s hand-written bindings in
`app-mobile/lib/functions/wallet_core_ffi.dart`. Every fallible function
returns a heap-allocated, NUL-terminated JSON C string —
`{"...fields":...}` on success, `{"error":"..."}` on failure — which
must be released via `wc_free_string` after use.

| Function | Returns | What it does |
|---|---|---|
| `wc_generate_keypair()` | `{"privateKeyHex","address"}` | Generates a fresh keypair. |
| `wc_keypair_from_private_key(private_key_hex)` | `{"privateKeyHex","address"}` or `{"error"}` | Parses a hex private key. |
| `wc_address_from_private_key(private_key_hex)` | `{"address"}` or `{"error"}` | Returns just the address for a hex private key. |
| `wc_sign_personal(private_key_hex, message)` | `{"signature"}` or `{"error"}` | Signs a UTF-8 message with EIP-191 `personal_sign`. |
| `wc_sign_personal_bytes(private_key_hex, message_ptr, message_len)` | `{"signature"}` or `{"error"}` | Signs raw bytes (not necessarily UTF-8). |
| `wc_verify_personal(address, message, signature_b64)` | `i32`: `1` valid, `0` invalid, `-1` malformed args/signature | Verifies a signature against a claimed address. |
| `wc_recover_personal_signer(message, signature_b64)` | `{"address"}` or `{"error"}` | Recovers the signer's address from a signature. |
| `wc_generate_mnemonic()` | `{"mnemonic"}` | Generates a fresh 12-word BIP39 mnemonic. |
| `wc_keypair_from_mnemonic(mnemonic, index)` | `{"privateKeyHex","address"}` or `{"error"}` | Derives a keypair from a mnemonic at BIP44 path `m/44'/60'/0'/0/{index}`. |
| `wc_free_string(ptr)` | `void` | Frees a string returned by any of the above. **Must** be called on every returned pointer to avoid leaking the Rust-allocated buffer. |

`app-mobile/lib/functions/wallet_core_ffi.dart`'s `WalletCoreFFI` class
wraps all of this into a typed Dart API (`generateKeypair()`,
`signPersonal(...)`, etc.), and `trovo-sdk.dart` calls that class. The
Dart-side code is complete and in active use in that file — **what's
missing is the native library it loads at runtime**; see DEPLOYMENT.md
section 3 for the full detail.

## Who actually consumes this today — the honest accounting

| Consumer | Status | Evidence |
|---|---|---|
| **app-web** | **Wired up and in active use.** | `app-web/src/walletCore/` holds a committed copy of the wasm build output. `app-web/src/utils/trovoSDK.ts` imports it directly (`from '../walletCore/wallet_core.js'`) and is itself imported by roughly a dozen pages/components, including `walletOperations.tsx`, `importWallet.tsx`, `accountRecovery/main.tsx`, `createAccount/backup.tsx`, `createAccount/registrationForm.tsx`, `dashboard/wallet/walletView.tsx`, `dashboard/tokenize/confirmTokenizationDetails.tsx`, `dashboard/sharedAccess/landing.tsx`, `dashboard/p2p/orderDetail.tsx`, `pay/payLanding.tsx`, and `tokenizedAssetActionModals.tsx`. |
| **tm-web** | **Not wired up.** | No reference to `wallet-core`, `wallet_core`, or `walletCore` anywhere in `tm-web/package.json` or `tm-web/`'s source tree. |
| **app-mobile** | **Dart bindings written and used; native library not built or bundled.** | `app-mobile/lib/functions/wallet_core_ffi.dart` (typed `dart:ffi` bindings over `src/ffi.rs`) is imported and called by `app-mobile/lib/functions/trovo-sdk.dart`, and a test exists at `app-mobile/test/wallet_core_ffi_test.dart`. But no `.so`/`.a`/`.dylib` for `wallet-core` exists anywhere under `app-mobile/android` or `app-mobile/ios`, no Gradle/Podfile/Xcode config references it, and no CI step builds or places one — confirmed by searching those directories for `jniLibs`, `libwallet_core`, and `XCFramework` (no matches). At runtime, `WalletCoreFFI.instance`'s first access would throw when `DynamicLibrary.open`/`.process()` fails to find the library/symbols, unless someone has built and placed it manually and out-of-band. |

**Do not describe `wallet-core` as fully integrated across the mobile
app** — the Rust and Dart code for that path exist and are correct as
far as they go, but the build/packaging step that would make it actually
work at runtime is unfinished (see DEPLOYMENT.md §3.3 for what's needed
to finish it).
